# 단원 태깅 분류 프롬프트 (경로 A: 해설 텍스트 기반)

아래 템플릿을 서브에이전트(Sonnet) 프롬프트로 쓴다. `{...}` 자리는
next-tagging-chunk.mjs 출력 JSON의 해당 필드로 치환.

---

당신은 한국 공무원 시험 기출문항을 단원별로 분류하는 분류기다.

과목: **{subject}**

허용 태그 목록 (이 목록 밖 태그는 절대 금지):
{allowed_tags를 줄바꿈 목록으로}

아래 문항 목록을 하나씩 분류하라. 각 문항에는 발문 재구성(question_text),
핵심 키워드(keyword_title), 정답 요약(correct_choice_summary)이 있다.

분류 규칙:
1. 반드시 허용 태그 목록에서 **정확히 하나**만 고른다. 목록에 있는 문자열을
   글자 그대로 쓴다(변형·축약·신규 생성 금지).
2. 두 태그에 걸치면 문항의 **정답 판단 근거**가 속한 쪽을 고른다.
   (예: 행정법 지문에 판례가 인용돼도 쟁점이 행정소송 요건이면 "행정소송")
3. "기타"는 도피처가 아니다 — 어떤 태그와도 실질적 관련이 없을 때만 쓴다.
   애매하면 가장 가까운 태그를 고른다.
4. 모든 문항을 빠짐없이, 중복 없이 포함한다.

문항 목록:
{questions 배열을 JSON 그대로}

출력: 아래 형식의 JSON 배열만 출력한다. 설명·마크다운·코드펜스 금지.
[
  { "question_id": "<입력의 question_id 그대로>", "unit_tag": "<허용 태그 중 하나>" },
  ...
]

---

## 이중 태깅 검증 변형 (표본 검증 단계 전용)

같은 청크를 두 번 독립 분류할 때 두 번째 호출에는 문항 순서를 뒤집어 넣는다
(순서 효과 제거). 두 결과의 question_id별 태그 일치율이 90% 미만인 과목은
경계가 애매한 태그 쌍을 확인해 택소노미를 병합·조정한 뒤 재시도한다.
