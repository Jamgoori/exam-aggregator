# 한국사능력검정시험(한능검) 등록 — 2026-09-12

공무원 시험이 아닌 시험을 처음 들인 작업이라, 다음 회차를 추가하거나 비슷한
시험(기본·고급, 다른 자격시험)을 들일 때 알아야 할 것을 적어둔다.

## 지금 들어 있는 것

- **심화 50~79회 30장**(2020~2026) + 정답표 30장 + `paper_answers` 30건.
- 스크립트: `scripts/upload-korean-history-exam.mjs`
  (`--dir <폴더> [--dry] [--only 50,51]`). 문제지 업로드·정답표 업로드·정답 저장을
  한 번에 하고, 이미 있는 회차는 건드리지 않으므로 재실행해도 안전하다.
  새 회차는 문제지·정답표 PDF를 한 폴더에 넣고 `--dry` 로 먼저 돌려볼 것.

## 공무원 기출과 어디가 다른가

| 축 | 공무원 | 한능검 |
|---|---|---|
| `exam_types.name` | 국가직·지방직… | `한능검` |
| `subjects` | 과목마다 한 행 | **전용 행 하나**(`korean-history-exam` / "한국사능력검정시험") |
| `level` | 9급·7급… | `심화` |
| `round` | 1(경찰만 2·3차) | **회차 그 자체**(50~79) |
| `year` | 파일명 | **정답표 PDF 생성일**(= 정답 공개일 = 시험 당일) |
| 문항/보기 | 20·25문항 4지선다 | 50문항 **5지선다** |

- **공무원 "한국사"(`korean-history`) 과목에 절대 붙이지 말 것.** 문항 수도 범위도
  다른 시험이라 섞이면 ㅎ 탭의 한국사 목록이 통째로 못 쓰게 된다. 전용 과목 행에만
  붙이고, 그 과목은 과목 색인(초성)에서 감춘 뒤 맨 앞의 "한능검" 탭 하나로 들어간다
  (`src/lib/korean-history-exam.ts`, `components/subject-index-tabs.tsx`).
  그 탭이 가는 곳은 시험 허브 `/exams/한능검-심화`다.
- **연도를 파일명에서 찾지 말 것** — 파일명에 없다. 정답표 PDF 의 `CreationDate` 를
  쓴다. 문제지 표지의 "2020년도 제50회"와 대조해 50·52·73·77회를 눈으로 확인했고
  전부 일치했다(연도별 회차 수도 2023년까지 6회, 2024년부터 4회로 알려진 일정과 맞다).
- **주소 규칙을 한 줄 고쳤다**(`packages/core/src/paper-slug.ts`). 제목이 이미
  "제50회"라고 말하는데 `round=50` 이 또 붙어 `…-제50회-심화-50회` 가 됐다. 원래
  경찰("공채 2차")을 위해 `N차` 를 보던 자리에 `N회` 를 같이 본다. 등록된 문제지
  4,869장 전수로 슬러그 중복 0건을 확인했다.

## 정답표 파싱 — 범용 파서를 쓰지 않는 이유

한능검 정답표는 (문항번호|정답|배점) 다섯 묶음이 한 표에 들어가는 고정 판형이라,
`answer-grid-parser.mjs`(과목 × 문항 격자) 의 대상이 아니다. 전용 파서가 스크립트
안에 있고, 판형이 둘이다:

- **원문자판**(①~⑤) — 28장.
- **맨숫자판** — 58회·73회 두 장. 정답 숫자와 배점 숫자가 생김새가 같아서, 행 안의
  숫자를 `[번호, 정답, 배점]` 3개씩 끊어 읽고 **번호 집합이 정확히 1~50, 정답이
  1~5, 배점이 1~3** 인지로 검증한다. 이 두 장은 파싱 결과를 PDF 텍스트와 손으로
  전량 대조했다.
- **63회 42번은 "없음"**(문항 이의심사 결과 오류 판정 → 응시자 전원 정답). 규약대로
  `answers` 자리에는 1 을 넣고 `voided_questions: [42]` 로 처리했다.

어느 판형이든 1~50 이 다 차지 않으면 그 회차는 **저장하지 않고 실패로 보고**한다 —
추측해서 채우지 않는다.

## 문항 이미지 크롭 — 30장 중 12장만 가능하다

**PDF 절반 이상이 스캔본이다.** 30장 중 18장은 텍스트 레이어가 통째로 없고(전체
글자수 0), 12장만 있다. 같은 시험·같은 판형인데 회차마다 갈리므로 **한 장만 열어
보고 "이 시험은 스캔본"이라고 판단하지 말 것** (처음에 50회만 보고 전부 스캔본이라
적었다가 정정했다). 판단은 전 회차의 `getTextContent()` 글자수를 세어서 한다.

- 텍스트 레이어 있음(크롭 완료, 각 50/50): **51·52·54·56·58·62·70·71·72·75·76·77회**
- 스캔본 18장 → **OCR 경로로 12장**(`npm run crop-scanned-questions`,
  `docs/agents/crop-question-images.md` 의 "스캔본 OCR 경로" 절과 그 아래 정정 절):
  **50·53·55·59·60·61·68·69·73·74·78·79회**. 2026-09-12 에는 50회 한 장뿐이었는데,
  발문 줄이 지워지던 baseline 버그와 마커 되살리기 네 라운드로 여기까지 왔다
  (그쪽 문서에 실측 실패 사례가 전부 있다). 50회는 발문이 빠진 이미지가 13개
  올라가 있었어서 다시 잘라 덮어썼다. 남은 6장(57·63·64·65·66·67회)은 마커
  3~7개가 재판독으로도 안 읽혀 개수 게이트에서 막혀 있다.

**현재 문항 이미지 완비 24/30장.** 나머지 6장은 "문제별 풀기"만 비활성이고
CBT·채점·오답노트는 정상이다. 확인은 `scripts/dump-scanned-crops.mjs` 로 잘라
**발문부터 마지막 선지까지** 눈으로 볼 것 — 개수·대조 수치만 보고 넘긴 자리에서
사고가 났다.

크롭한 12장은 `question_images` 가 문항 수와 정확히 일치하고, 문제지 안에서 이미지
폭도 하나로 통일돼 있다(51회 1166px, 62회 1141px, 77회 1111px). 세트문제는 두 장에
하나씩 있다 — 62회 `[49~50]`, 72회 `[47~48]`. **이 세트 때문에 크롭 로직을 하나
고쳤다**(안내문 조각의 baseline 이 어긋나 병합이 조용히 깨지던 것 —
`docs/agents/crop-question-images.md` 의 2026-09-12 절). 스캔본 18장은 "문제별
풀기"가 비활성이고, CBT 는 PDF 뷰어 + OMR 로 정상 동작한다(정답이 있으므로
채점·오답노트 정상).
- **해설 없음.** 해설 배치는 과목 단위라 이 과목을 대상에 넣을지는 별도 결정
  (`explanation_excluded_subjects`).
