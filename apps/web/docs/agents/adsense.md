# 구글 애드센스 (광고 수익)

코드로 할 수 있는 것은 **게시자 ID 하나**와 그 ID 가 만드는 두 가지 —
`<head>` 의 로더 스크립트와 `/ads.txt` — 가 전부다. 나머지(승인 심사, 광고를 어디에
띄울지, 어느 페이지를 제외할지, 지급 계좌)는 애드센스 대시보드에서 한다.
여기에는 **코드 밖 절차**와 **되돌리기 어려운 사고**를 적어 둔다.

관련 파일:

| 파일 | 하는 일 |
|---|---|
| `src/lib/adsense.ts` | 게시자 ID 정본(`PUBLISHER_ID`). `ca-pub-…` / `pub-…` 두 형태를 여기서 만든다 |
| `src/app/layout.tsx` | `<head>` 안의 로더 `<script async>` |
| `src/app/ads.txt/route.ts` | `/ads.txt` 본문 |
| `src/app/privacy/page.tsx` | 광고 고지(위탁 표 5항·쿠키 9항·부칙) — 광고가 켜지면 함께 나타난다 |
| `src/lib/geo-block.ts` | `/ads.txt` 를 해외 IP 차단에서 통과시키는 설비 경로 목록 |
| `.github/workflows/domain-check.yml` | 배포된 사이트에서 로더·`/ads.txt` 를 밖에서 실제로 확인 |

## 1. 가입 직후 — 순서대로

1. **게시자 ID 를 코드에 박는다.** 애드센스 → 계정 → 설정 → 계정 정보의
   `pub-0000000000000000`(또는 "코드 가져오기" 스니펫의 `ca-pub-…`) 을
   `src/lib/adsense.ts` 의 `PUBLISHER_ID` 에 넣는다. 숫자만 넣어도 되고 접두사를
   붙여 넣어도 된다 — 파싱이 받아 준다.
   환경변수(`NEXT_PUBLIC_ADSENSE_CLIENT`)는 계정을 옮길 때나 프리뷰에서 잠깐 시험할
   때만 쓴다. 정본을 env 로 옮기지 말 것: 값이 빠지면 광고가 조용히 멈추고 `/ads.txt`
   까지 404 가 된다.
2. **개인정보처리방침 시행일을 맞춘다.** `src/app/privacy/page.tsx` 의
   `ADSENSE_POLICY_EFFECTIVE_DATE` 를 **광고를 켜는 날**로 두고, 그보다 **7일 이상
   앞서** 공지사항(`/notices`)에 방침 변경을 올린다. 방침 본문(위탁 표·쿠키 항목)은
   게시자 ID 가 설정되는 순간 함께 나타나므로 따로 손댈 것이 없다.
3. **배포하고 밖에서 확인한다.** Actions → "도메인 점검" → Run workflow.
   `<head>` 의 로더와 `/ads.txt` 를 실제 사이트에서 확인한다(광고를 아직 안 켰으면
   두 항목은 건너뛴다고 요약에 적힌다).
4. **애드센스에서 "사이트 검토 요청"** 을 누른다. 스니펫을 직접 붙이라고 안내하지만,
   위 1~3 이 끝났으면 이미 같은 스크립트가 `<head>` 에 들어 있으므로 추가 작업이 없다.
   심사는 보통 며칠~2주. 이 기간에 스크립트를 떼면 심사가 실패한다.
5. **승인되면 광고 단위를 만들고 슬롯 ID 를 넣는다.** 애드센스 → 광고 → 광고 단위
   기준에서 자리마다 하나씩 만들고, 받은 슬롯 번호를 Vercel 환경변수에 넣는다
   (아래 3절의 표). 자리는 코드가 이미 잡아 두었다.
   **자동 광고는 켜지 말 것** — 멤버십 회원 구분이 통째로 무너진다(3절).

## 2. 사고 방지선

- **CBT 풀이 화면(`/papers/*/cbt`)과 복습 세션은 자동 광고에서 반드시 제외한다.**
  애드센스 → 광고 → 자동 광고 → 페이지 제외. OMR 버튼 위에 광고가 뜨면 오클릭이
  쌓이는데, 무효 트래픽은 경고 없이 **계정 정지**로 이어진다. 정지는 되돌리기 어렵다.
  (같은 이유로 헤더·푸터에 붙는 고정 FAB 근처도 피한다.)
- **자기 광고를 절대 클릭하지 않는다.** 확인이 필요하면 광고가 "나오는지"만 보고,
  클릭은 하지 않는다. 지인에게 클릭을 부탁하는 것도 같은 위반이다.
- **`/ads.txt` 를 정적 파일로 다시 만들지 말 것.** 게시자 ID 가 로더와 ads.txt 두 곳에
  나뉘어 적히면 한쪽만 고치는 사고가 난다(그래도 화면에는 아무 표시가 없다).
- **로더 스크립트를 `next/script` 로 바꾸지 말 것.** 심사 크롤러와 자동 광고는 서버가
  보낸 HTML 에서 태그를 찾는다 — `afterInteractive` 는 하이드레이션 뒤에 태그를 심어서
  HTML 에 없을 수 있고, `beforeInteractive` 는 우리 코드보다 먼저 프리로드돼 본문
  표시를 늦춘다. 이유는 `layout.tsx` 의 주석에 남겨 두었다.
- **`ads.txt` 네 번째 칸(`f08c47fec0942fa0`)은 우리 계정 값이 아니다.** 모든 애드센스
  게시자가 같은 값을 쓰는 구글의 인증 기관 ID 다 — "우리 값으로 바꿔야 하나" 싶어도
  건드리지 말 것.
- **해외 IP 차단(`GEO_BLOCK`)을 켤 때**: `/ads.txt` 는 `lib/geo-block.ts` 의
  `INFRA_FILES` 에, 구글 광고 크롤러(`Mediapartners-Google`·`AdsBot-Google`)는
  `CRAWLER_UA` 에 이미 들어 있다. 둘 중 하나를 지우면 광고가 "크롤러 오류"로 멈춘다.
- **유럽·영국 방문자가 있으면** 애드센스가 인증 CMP(동의 관리 플랫폼)를 요구한다.
  국내 서비스라 실제 비중은 미미하지만, 애드센스의 "구글 인증 CMP 사용" 옵션을 켜
  두면 구글 것으로 처리된다(코드 변경 없음). `GEO_BLOCK` 을 켜 둔 상태라면 애초에
  유럽 트래픽이 들어오지 않는다.

## 3. 광고와 유료 멤버십 — 누구에게 보이나

**비로그인 + 무료 회원에게만 보인다.** 결제(`paid`)·출석 보상(`attendance`)으로 기간을
들고 있는 사람과 관리자에게는 보이지 않는다.

| 파일 | 하는 일 |
|---|---|
| `packages/core/src/membership.ts` | `isAdFreeMembership` — 광고를 뺄 자격 판정 |
| `src/lib/ads.ts` | `shouldShowAds()` — 위 판정 + 관리자 + 설정 여부 |
| `src/components/ad-banner.tsx` | 자리 하나. `Suspense` 경계와 높이 예약 |
| `src/components/ad-slot.tsx` | `<ins>` + `adsbygoogle.push` |
| `src/lib/ad-slots.ts` | 자리별 광고 단위 슬롯 ID(환경변수) |

- **`isPremiumMembership` 으로 거르지 말 것.** 전면 무료 이벤트(`FREE_UNTIL`) 동안
  로그인한 사람 전원에게 `true` 다. `hasOwnPremiumPeriod` 도 안 된다 — 가입 체험의
  만료가 `trialExpiresAt` 때문에 `FREE_UNTIL` 까지 박혀 있어 역시 전원 `true` 가 된다.
  둘 중 아무거나 쓰면 "무료 회원에게도 광고"가 조용히 "비로그인에게만 광고"로 바뀌는데,
  화면상 차이가 없어서 알아채지 못한다. 그래서 남은 기간이 아니라 기간의 **출처**를 본다.
- **판정은 반드시 `Suspense` 경계 뒤에서.** 로그인 상태는 런타임 데이터라 정적
  셸(`layout.tsx`)에서 읽으면 셸이 통째로 동적이 되어 문제지 색인 구조가 깨진다
  (AGENTS.md 의 SEO 금지선). `ad-banner.tsx` 가 그 경계를 들고 있다.
- **셸에는 높이만 잡아 둔 빈 칸이 들어간다(CLS).** 방문자 다수가 결국 광고를 받으므로
  처음부터 그 높이를 비워 두면 밀림이 없다. 광고를 빼주는 소수에게는 이 칸이 한 번
  접히는데, 그쪽을 기준으로 잡으면 다수가 매번 밀리는 것과 맞바꾸는 셈이다.
- **⚠ 자동 광고를 켜면 이 판정이 통째로 무력해진다.** 대시보드의 자동 광고는 로더만
  보고 페이지에 광고를 꽂으므로 결제 회원·관리자 화면에도 나간다. 관리자에게 나가면
  자기 광고 클릭 사고로 이어진다. 멤버십 구분을 유지하려면 자동 광고는 꺼 두고, 아래
  손 배치 자리만 쓴다.

### 광고 자리 (손 배치)

| 자리 | 위치 | 슬롯 환경변수 |
|---|---|---|
| 홈 | 마무리 CTA 아래 | `NEXT_PUBLIC_ADSENSE_SLOT_HOME` |
| 기출문제 목록 | `/papers` 카드 목록 하단 | `NEXT_PUBLIC_ADSENSE_SLOT_PAPERS` |
| 문제지 상세 | 본문 끝, "같은 과목 목록" 위 | `NEXT_PUBLIC_ADSENSE_SLOT_PAPER` |

슬롯 ID 가 없는 자리는 조용히 빠진다. 자리를 늘릴 때는 `AdPlacement` 에 이름을 추가하고
그 화면에 `<AdBanner placement="…" />` 를 직접 붙인다 — **푸터·헤더처럼 전역에 달지 말 것.**
몰입형 풀이 화면(CBT·복습)·결제·로그인까지 따라 들어간다. 문제 이미지 사이에도 두지
않는다: 보기를 고르는 손가락 아래로 광고가 들어와 오클릭(=무효 트래픽)이 된다.

## 4. 수익이 0 으로 보일 때 확인 순서

1. `/ads.txt` 가 200 이고 `pub-` 번호가 맞는가 (Actions "도메인 점검").
2. `<head>` 에 로더가 있는가 — 브라우저에서 "페이지 소스 보기" 후 `adsbygoogle` 검색.
   (개발자 도구의 Elements 가 아니라 **소스**를 볼 것. 심사 크롤러가 보는 것과 같다.)
3. 애드센스 → 광고 → 사이트별에서 도메인 상태가 "준비됨"인가.
4. 광고 차단기를 켠 브라우저로 보고 있지 않은가.
5. 자동 광고가 켜져 있고, 제외 페이지 목록에 사이트 전체(`/`)가 잡혀 있지 않은가.
