# 기존 해설 개념 재분류 지시문 (루틴용)

이미 만들어진 해설에 정본 개념(`concept_id`)을 붙이는 반복 작업이다. 해설 본문은
건드리지 않는다 — 붙이는 축만 추가한다.

> 이 파일의 원본은 **이 레포**다. 해설 생성 지시문(`explanation-prompt.md`)과 달리
> Supabase Storage 배포 절차가 없다. 루틴을 만들 때 이 내용을 그대로 프롬프트에
> 넣거나, 세션에서 `git fetch origin master` 후 이 파일을 읽게 하면 된다.

## 왜 이 작업이 필요한가

해설 5만 개가 이미 있는데 전부 `concept_id` 가 null 이다. 정본 목록을 세워도 별칭
매칭으로는 안 붙는다 — 실측 커버리지가 국어 0.2% · 한국사 1.3% · 영어 0.1% 였다.
`keyword_title` 이 개념 이름이 아니라 문항마다 다른 문장이기 때문이다:

```
IPSec의 두 동작 모드 — 전송모드와 터널모드
IPSec의 구성 요소 — AH, ESP, SA
IPsec ESP에서 암호화되는 필드
```

셋 다 사람이 읽으면 `VPN과 IPSec` 인 게 즉시 보이지만 문자열 비교로는 못 붙인다.
그래서 모델이 읽고 정본 목록에서 고른다.

**문항 이미지는 안 읽는다.** `keyword_title` 과 `question_text` 만으로 결정된다.

## 처리 순서 (매 firing)

0. 시작 시각을 `date +%s` 로 기록한다. 배치를 하나 저장할 때마다 경과를 확인해
   **90분을 넘기면 그 배치까지만 마치고 정상 종료**한다 (같은 방향 세션끼리 겹치는
   것을 막는 장치 — 해설 배치와 같은 규칙).
1. `node scripts/next-concept-chunk.mjs --limit 60` 으로 청크를 받는다.
   `done: true` 면 종료한다.
   **과목은 매번 스크립트가 고른다 — `--subject` 를 붙이지 말 것.** 전 과목을 훑어
   미분류 해설이 남은 과목을 내려주고, 한 과목이 바닥나면 다음 호출이 곧바로 다음
   과목을 준다. 출력의 `tail: true` 는 그 과목이 끝물이라는 뜻이다(다음은 다른 과목).
2. 출력의 `concepts` 가 그 과목의 **정본 목록**이다. `items` 의 문항마다 그 안에서
   이름 하나를 골라 **글자 그대로** 적는다.
3. 결과를 JSON 배열 파일로 쓴다:
   ```json
   [
     { "question_id": "uuid", "concept": "VPN과 IPSec" },
     { "question_id": "uuid", "concept": "?침해사고 대응" }
   ]
   ```
4. `node scripts/save-concepts.mjs <파일경로>` 로 저장한다.
5. 출력의 `unmatched` 가 있으면 **그 문항만** 목록에서 다시 골라 재저장한다
   (이름을 잘못 베낀 것이다). 2회 넘게 실패하면 그대로 두고 넘어간다.
6. `done: true` 가 나오거나 90분 컷오프까지 1~5를 반복한다.

## 고르는 규칙

1. **목록에 있는 이름만 쓴다.** 지어내면 표기가 다시 표류하고 개념별 분포가 조용히
   어긋난다. 목록에 마땅한 게 정말 없을 때만 `"?새 이름"` 으로 제안한다
2. **발문이 가리키는 대상**으로 고른다. 선지가 다른 개념과 비교한다고 그쪽으로 옮기지
   않는다 — "대칭키 암호 알고리즘에 대한 설명으로 옳지 않은 것은?"은 선지에 공개키가
   나와도 `대칭키 암호` 다
3. **독해 문항은 지문 주제가 아니라 묻는 능력을 고른다.** `kind: "skill"` 로 표시된
   것들이다. `keyword_title` 이 "조선 후기 상업의 발달"이어도 개념은 `주제 파악`
   이거나 `세부 내용 일치` 다 — 지문은 재출제되지 않아 주제를 개념으로 세우면
   사용자에게 해줄 말이 없다. 이때 `question_text`(발문)가 결정적이다
4. **애매하면 상위 개념으로.** 두 개념 사이에서 갈리면 더 거친 쪽을 고른다. 찍어서
   붙이면 진단이 조용히 틀린다
5. **`?` 제안은 아껴 쓴다.** 문항 서너 개 분량의 주제만 개념이 될 수 있다. 한두 문항
   짜리 지엽적 주제는 제안하지 말고 가장 가까운 상위 개념을 고른다

## 제안(`proposed`) 처리

`save-concepts.mjs` 출력의 `proposed` 는 사람이 볼 목록이다. **루틴이 알아서 개념을
추가하지 않는다** — 해설봇은 `concepts`/`concept_aliases` 에 쓸 권한이 없다(사전은
service_role 로만 바꾼다). 세션 끝에 `proposed` 를 모아서 보고만 한다.

소유자는 같은 이름이 **3회 이상** 나온 것만 정본에 넣는다. 그보다 적으면 진단 표본이
안 나오므로 상위(단원)로 흡수하는 게 맞다 — 과목당 개념은 20~40개를 유지한다.

## 목록이 없는 과목

`next-concept-chunk.mjs` 는 정본 목록이 있는 과목만 내려준다. 목록이 없는 과목은
붙일 데가 없어 건너뛴다.

그 과목의 목록을 세울 재료가 필요하면:

```
node scripts/next-concept-chunk.mjs --mine --limit 200
```

목록이 없는 과목 중 해설이 가장 많은 과목의 표기를 **무작위 위치 블록 5개**로 나눠
뽑아 준다(앞에서부터 자르면 같은 시험지가 몰린다). 그걸 읽고 **20~40개** 개념 초안을
낸다. 표기 하나마다 개념을 만들지 말 것 — 그러면 300개가 된다.

초안은 등록하지 말고 `scripts/data/concepts-seed.json` 형식으로 파일에 남긴다.
등록은 소유자가 SQL 로 한다.

## 금지선

- **`keyword_title` 을 UPDATE 하지 말 것.** 화면에 그대로 보여주는 값이다
- **이미 붙은 `concept_id` 를 덮어쓰지 말 것.** `save-concepts.mjs` 가 막고 있다
  (`skipped_existing` 으로 보고). 같은 문항이 실행할 때마다 다른 개념이 되면 진단
  이력이 깨진다
- **미매칭을 "기타"로 뭉치지 말 것.** 뭉치는 순간 진단이 죽는다
- **해설 본문 필드를 건드리지 말 것.** 이 작업은 `concept_id` 만 쓴다
