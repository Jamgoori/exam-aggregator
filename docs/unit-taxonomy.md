# 문항 단원 태깅(unit_tag) 설계 — 초안

AI 약점진단·약점 히트맵·맞춤 모의고사의 공통 전제인 문항 단원 분류 체계.
상태: **설계 초안 (소유자 리뷰 대기)**. 태깅 배치 실행 전임 — 아직 DB의
`questions.unit_tag`는 전부 null이다.

## 저장 구조

- 태그는 기존 `questions.unit_tag`(text) 컬럼에 그대로 저장한다. 스키마 변경 없음.
- 태그 문자열이 곧 화면 표시 이름이다(약점 히트맵에 그대로 노출). 문항은
  paper를 거쳐 과목과 연결되므로 태그는 과목 안에서만 유일하면 되고, 과목
  접두사를 붙이지 않는다.

## 택소노미 원본: `scripts/unit-taxonomy.json`

단일 진실 파일. 태깅 스크립트·해설 루틴 연동·검증 스크립트가 전부 이 파일만
읽는다. 구조:

- `taxonomies`: 과목명 → 태그 배열. **모든 배열 끝에 "기타" 필수** (분류
  불확실 시 폴백 버킷).
- `aliases`: 동일 체계를 공유하는 과목 매핑. 7급/9급 동명 과목(예: `경제학` →
  `경제학개론`), 어학 6과목(독어·러시아어·불어·스페인어·일어·중국어 →
  `어학공통`) 등. 과목 ~125개를 정의 ~90개로 압축한다.
- `version`: 날짜 기반(`YYYY-MM-DD.n`). 태그 이름을 바꾸면 이미 저장된
  `unit_tag` 값도 함께 UPDATE해야 하므로, 변경 시 버전을 올리고 마이그레이션을
  같이 챙긴다.

태깅 시 AI는 해당 과목의 목록 **안에서만** 고르도록 강제한다(자유 생성 금지).
목록에 없는 답이 오면 "기타"로 폴백.

## 태그 굵기 규칙

- 과목당 6~13개. 기준은 수험 교재 표준 목차 단위(편/장 수준).
- 너무 잘게 쪼개면 히트맵 칸이 비어 보이고, 너무 굵으면 진단이 무의미하다.
- 판정은 데이터로 한다 (아래 검증 프로토콜의 분포 검사):
  - "기타" 비율 > 10% → 목록에 구멍. 태그 추가.
  - 한 태그 > 40% → 너무 굵음. 분할.
  - 한 태그 < 1% → 너무 잘음. 인접 태그와 병합.

## 태깅 파이프라인 (3경로, 전부 증분)

모든 경로는 `unit_tag IS NULL`인 문항만 처리한다. 나중에 새 시험지가 추가되면
그 문항만 자동으로 이어서 처리되므로 "몰아서 한 번에" 할 필요가 없다.

- **경로 A — 해설 있는 문항 (~1.2만, 최우선)**: `question_explanations.question_text`
  가 이미 텍스트로 있으므로 이미지 없이 텍스트 분류만 한다. 요청당 40문항
  내외 묶음 처리, 출력은 태그 하나씩. 저렴·고속. 이것만 끝나도 히트맵·맞춤
  모의고사 개발을 시작할 수 있다.
- **경로 B — 해설 루틴 무임승차 (나머지, 추가비용 0)**: 해설 배치 루틴이
  어차피 문항 이미지를 읽고 풀이하므로, 해설 저장 시 unit_tag도 함께 저장하게
  프롬프트에 한 줄 추가한다. 남은 해설 진행 속도 그대로 태깅이 따라온다.
- **경로 C — 태깅 전용 루틴 (선택, 가속용)**: 약점진단 출시를 해설 완주보다
  앞당기고 싶을 때만. 이미지 15~20장 묶음 분류라 해설 대비 수십 배 빠르다.
  응시 많은 시험지부터 우선 처리(히트맵은 유저가 푼 문항의 태그만 있으면
  그려지므로 체감 커버리지가 빨리 오른다).

## 검증 프로토콜 (사람 개입 없음)

1. **이중 태깅 일치율**: 과목당 표본 100~200문항을 독립적으로 2회 분류.
   일치율 90% 미만이면 경계가 애매한 태그를 병합 후 재시도.
2. **분포 검사**: 위 굵기 규칙의 3개 임계값을 자동 리포트로 확인.
3. 소유자가 보는 것은 최종 히트맵의 태그 이름이 수험생에게 익숙한 용어인지
   정도 — 표준 교재 목차 용어라 대부분 통과 예상.

## 안전 성질

- 태그는 표시·집계 전용이다. 정답·채점·오답 기록(`paper_answers`,
  `cbt_attempt_answers`, `user_question_status`)과 완전히 분리돼 있어 태그가
  틀려도 서비스가 깨질 곳이 없다.
- 체계를 갈아엎어도 재태깅 배치 한 번(UPDATE)이면 끝난다.
