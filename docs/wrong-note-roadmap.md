## 0. 현재 상태 요약 (출발점)

이미 갖춰진 것:

| 자산 | 위치 | 비고 |
|---|---|---|
| 문항 단위 정오 기록 | `cbt_attempts` + `cbt_attempt_answers` | 선택지·정오·응시별 전부 보존 |
| 오답 집계 로직 | `src/lib/wrong-notes.ts` | 틀린 횟수, "극복"(최근 응시에서 맞힘) 판정까지 계산 |
| 오답노트 UI | 마이페이지 탭 → 과목 → 문제지 드릴다운 | 문항 이미지·정답·AI 해설 표시 |
| 문항별 개념 키워드 | `question_explanations.keyword_title` | 해설 배치 루틴이 자동 축적 중 — **약점 진단의 핵심 재료** |
| 단원 태그 컬럼 | `questions.unit_tag` | 스키마에 "오답노트 단원별 분석용"으로 예약만 돼 있고 미사용 |
| CBT 솔버 | `cbt-solver.tsx` 일식 | 문제지 단위 풀이 전제 |
| 시간당 제한 패턴 | `explanation_access_log` | "일 1회" 제한 구현 시 참고 가능 |

핵심 한계: 모든 것이 **"문제지" 단위**로 묶여 있다. 과목 오답노트도 문제지 카드
목록이지 문항이 평평하게 모이지 않고, CBT도 문제지 하나만 풀 수 있다. 이번
로드맵의 본질은 **오답 데이터의 기본 단위를 문제지에서 "문항"으로 내리는 것**이다.

## Phase 1 — 과목별 틀린문제 모아보기 (기반 겸 첫 기능)

**목표**: 과목 오답노트를 "문제지 카드 목록"에서 "그 과목에서 틀린 문항 전체를
한 화면에 펼친 목록"으로 확장. 이후 모든 기능(섞어풀기·진단)의 데이터 통로가 된다.

### 만들 것
- 과목 오답노트에 뷰 전환: 기존 "문제지별" 탭 + 신규 **"문항 모아보기"** 탭.
- 필터/정렬: 미극복만 · 2번 이상 틀림 · 최근 틀린 순 · 자주 틀린 순 · 연도/급수.
- 문항 카드는 기존 `wrong-note-question-card.tsx` 재사용(출처 문제지 표시만 추가).
- (선택) 인쇄/PDF 내보내기 — 기존 `print-button`/`explanation-auto-print` 패턴 재사용.

### 데이터 작업
- `getSubjectWrongNoteOverview`는 현재 요약만 주므로, 과목 단위로 문항
  상세(이미지·정답·해설)까지 합치는 `getSubjectWrongNoteQuestions` 계열 추가.
  `fetchQuestionMedia`/`fetchCorrectAnswers`/`fetchExplanations`가 이미
  다중 paper를 받으므로 조합만 하면 된다.
- **성능 주의**: 회독이 쌓인 사용자는 문항 수가 수백 개가 될 수 있다.
  페이지네이션 또는 "미극복 우선 + 더보기"로 시작하고, 무거워지면 그때
  집계 테이블(Phase 2의 `user_question_status`)로 옮긴다. 처음부터 캐시 테이블을
  만들지 않는다 — 파생 데이터는 파생인 채로 시작하는 게 되돌리기 쉽다.

### 완료 기준
과목 페이지에서 필터 걸고 문항만 쭉 넘겨보는 흐름이 실제 회독 10회+ 계정에서
2초 안에 뜬다.

## Phase 2 — 섞어풀기 (오답 재풀이 CBT)

**목표**: 선택한 오답들을 무작위로 섞어 CBT로 다시 풀고, 그 결과가 오답노트의
"극복" 상태에 반영되게 한다. 이 Phase가 스키마상 가장 중요한 결정 지점이다.

### 핵심 설계 결정: 문항 단위 상태 테이블 도입
현재 "극복"은 *같은 문제지를 통째로 재응시*했을 때만 갱신된다(파생 계산).
섞어풀기는 문제지 단위 응시가 아니므로, 파생만으로는 표현이 안 된다. 도입할 것:

```
review_sessions        -- 섞어풀기 세션 (user_id, 필터 조건 스냅샷, score, created_at)
review_session_items   -- 세션 문항 (session_id, question_id, selected_choice, is_correct)
user_question_status   -- 문항별 통합 상태 (user_id, question_id,
                       --   wrong_count, last_result, last_answered_at, source)
```

- `user_question_status`는 문제지 CBT 채점 시(`cbt-attempt.ts`)와 섞어풀기 채점 시
  양쪽에서 갱신한다. 오답노트 화면의 극복 판정을 이 테이블 기준으로 바꾸면
  "섞어풀기에서 맞히면 극복" 이 자연스럽게 성립한다.
- 기존 사용자 데이터는 `cbt_attempt_answers`에서 일회성 백필.
- **주의(RLS)**: 채점은 반드시 서버에서. `paper_answers`는 정답 유출 방지로
  일반 SELECT가 막혀 있으므로 섞어풀기 채점도 기존 CBT처럼 service role 경유.

### 만들 것
- 진입점: 과목 오답노트 상단 "섞어풀기 시작" 버튼 → 설정 시트
  (범위: 이 과목/전체, 미극복만 여부, 문항 수 10/20/전체, 순서 섞기).
- 풀이 화면: `cbt-solver`를 "가상 문제지"(문항 배열)를 받을 수 있게 일반화.
  문항마다 출처(문제지·번호)는 결과 화면에서만 노출(풀이 중엔 힌트가 되므로 숨김).
- 결과 화면: 맞힌 문항은 극복 처리 표시, 틀린 문항은 즉시 해설 노출.
- **엣지 케이스**: 이미지 미크롭 문항은 출제 대상에서 제외(`question_images` 존재
  검사), `voided_questions`(정답 없음 처리 문항) 제외, 5지선다/4지선다 혼재 시
  문항별 `choice_count` 사용(이미 문항 테이블에 있음).

### 완료 기준
오답 30개인 계정으로 "미극복만 20문항 섞어풀기" → 채점 → 오답노트로 돌아왔을 때
맞힌 문항에 극복 배지가 붙는 왕복 흐름 완주.

## Phase 3 — AI 약점 진단 (일 1회)

**목표**: 사용자의 오답 이력을 AI가 읽고 "무엇이 약한지 + 뭘 하면 되는지"를
하루 1회 리포트로 제공.

### 재료 (이미 있음)
- 오답 문항 × `question_explanations.keyword_title` 조인 → **틀린 개념 분포**.
  이게 이 기능의 승부처다. 해설 배치 루틴이 커버리지를 계속 넓히고 있으므로
  시간이 갈수록 진단이 정교해진다.
- 과목별 정오율·회독별 추이(`cbt_attempts.score` 시계열), 풀이 시간
  (`duration_seconds`), 반복 오답(wrong_count ≥ 2), 극복률.

### 스키마·제한
```
ai_diagnoses (user_id, diagnosis_date date, report jsonb, model, created_at,
              UNIQUE (user_id, diagnosis_date))
```
- "일 1회"는 unique 제약으로 강제 — `explanation_access_log`식 카운트보다 단순하고
  경합에도 안전. 당일 리포트가 있으면 캐시 표시, 없으면 생성 버튼 활성화.
- 리포트는 jsonb 구조화(취약 개념 top N + 근거 문항, 과목별 진단 한 줄, 추천
  액션)로 저장해 UI가 안정적으로 그리게 한다. 자유 서술 마크다운으로 받지 말 것.

### 생성 방식 결정: 온디맨드 API 호출 (권장)
| | 온디맨드 API (권장) | 야간 배치(기존 루틴식) |
|---|---|---|
| 비용 | 누른 사용자만, Haiku/Sonnet이면 회당 원 단위 | 전 활성 사용자 선생성 → 낭비 큼 |
| 신선도 | 버튼 누른 시점 데이터 | 최대 하루 지연 |
| 인프라 | 서버 액션 + API 키 1개 | 루틴 슬롯·겹침 관리 부담 추가 |

해설 배치와 달리 진단은 사용자가 요청할 때만 가치가 있으므로 온디맨드가 맞다.
입력은 원문 이미지가 아니라 **집계된 통계 + 개념 키워드 목록**(텍스트)만 넣으면
되므로 토큰이 작고, 구조화 출력(tool use)으로 받으면 파싱도 안정적이다.
단, 실비 API 과금이 새로 생기는 지점이므로 배포 전에 회당 비용 상한을 계산해 둘 것.

### 콜드 스타트 규칙
- 최소 데이터 문턱(예: 누적 오답 15개 또는 응시 3회) 미만이면 버튼 대신
  "○문제 더 풀면 진단을 받을 수 있어요" 안내 — 빈약한 데이터로 뻔한 리포트를
  주는 것이 기능 신뢰를 가장 빨리 깎는다.
- 개념 키워드가 없는 문항(해설 미생성)은 과목/문제지 수준 통계로만 반영.

### 리포트 → 행동 연결 (중요)
진단은 읽고 끝나면 안 된다. 각 취약 개념 항목에서 바로:
- "이 개념 틀린 문항 모아보기" (Phase 1 필터 딥링크)
- "이 개념만 섞어풀기" (Phase 2 프리셋 딥링크)
로 이어지게 한다. Phase 1·2가 선행돼야 하는 이유가 이것이다.

## UX 원칙 — 기능은 늘어도 표면은 늘리지 않는다

기능 4단계를 다 넣었을 때 사용자가 헷갈리는 것을 막는 장치. **혼란의 원인은
기능 개수가 아니라 진입점(메뉴·화면·버튼) 개수**다. 아래 원칙을 모든 Phase에
공통 적용한다.

### 1. 표면은 "오답노트" 하나
사용자에게 보이는 메뉴는 지금과 똑같이 오답노트 하나뿐이다. 모아보기·섞어풀기·
진단·복습은 별도 메뉴가 아니라 전부 그 안의 구성 요소다. 전체 화면 수 상한을
5개로 고정한다:

```
마이페이지 > 오답노트 (허브)
├─ ① 허브: "오늘 카드" + AI 진단 배너 + 과목 카드 목록  ← 기존 화면 확장
├─ ② 과목 상세: [문제지별 | 문항 모아보기] 탭 + 섞어풀기 버튼
├─ ③ 풀이 화면 (기존 CBT 솔버 재사용)
├─ ④ 풀이 결과
└─ ⑤ AI 진단 리포트
```

### 2. 기능 나열이 아니라 "다음 행동 하나"를 제시
허브 최상단에는 버튼 여러 개를 늘어놓지 않고, 상황에 맞는 **CTA 하나짜리
"오늘 카드"**만 둔다. 우선순위 규칙으로 자동 선택:

- 복습 예정 문항 있음 → "오늘 복습할 문항 12개 · 시작"
- 없고 미극복 오답 충분 → "미극복 24문항 섞어풀기"
- 진단 조건 충족 + 오늘 미수령 → "AI 약점 진단 받기"
- 아무것도 없음 → 최근 과목 이어보기

나머지 기능은 카드 아래·과목 상세에 평범하게 존재한다. 뭘 할지 고르게 하지
말고, 고른 결과를 보여준다.

### 3. 점진적 공개 — 데이터가 쌓여야 기능이 나타난다
신규 사용자에게 빈 진단·빈 섞어풀기를 보여주는 것이 혼란의 최대 원인이므로,
데이터 문턱 전에는 기능 자체를 렌더링하지 않는다 (회색 비활성 버튼도 두지 않음):

| 상태 | 보이는 것 |
|---|---|
| 오답 0 | 기존 오답노트 안내만 |
| 오답 1+ | 오답 목록 + 모아보기 탭 |
| 오답 ~10+ | 섞어풀기 버튼 등장 |
| 오답 ~15+ (or 응시 3회+) | AI 진단 배너 등장 |

처음 등장할 때 "새 기능" 배지 한 번이면 온보딩은 충분하다. 별도 튜토리얼을
만들지 않는다.

### 4. Phase 4는 새 기능이 아니라 기존 표면의 속성으로 흡수
Phase 4 항목들은 전용 화면·메뉴를 만드는 순간 "기능 6개짜리 앱"이 된다.
전부 기존 표면에 얹는다 — **새 화면 0개**가 Phase 4의 설계 제약이다:

- 복습 스케줄 → 허브 "오늘 카드"의 한 상태 + 섞어풀기 기본 프리셋
- 개념 태그 → 모아보기 탭의 필터 하나
- 전국 오답률 → 문항 카드의 배지 하나
- 문항 메모 → 문항 카드의 접힌 입력 필드
- PDF 내보내기 → 모아보기 탭의 인쇄 버튼
- D-day 플랜 → 진단 리포트의 확장 섹션

### 5. 설정을 노출하지 말고 기본값으로 흡수
섞어풀기 설정 시트(범위·문항 수·순서)는 첫 진입부터 펼치지 않는다. "미극복만 ·
20문항 · 섞기"를 기본값으로 즉시 시작하게 하고, 바꾸고 싶은 사용자만 "설정"을
연다. 진단도 옵션 없이 버튼 하나. 이름도 기능명("간격 반복", "진단")보다 행동
언어("다시 풀기", "약점 보기")를 쓴다.

## Phase 4 — 확장 아이디어 (우선순위 낮음, 검증 후 선별)

> 공통 제약: 위 UX 원칙 4번 — 어떤 항목도 새 화면·새 메뉴를 만들지 않고
> 기존 표면(허브 카드·모아보기 필터·문항 카드·진단 리포트)에 속성으로 얹는다.

1. **복습 스케줄(간격 반복)**: 틀린 문항을 1·3·7일 후 복습 큐에 자동 배치,
   마이페이지에 "오늘 복습할 문항 N개" 배지. `user_question_status`에
   `next_review_at`만 더하면 되므로 Phase 2 스키마 위에 얹기 쉽다. 스트릭
   (`streak.ts`)과 결합하면 재방문 동기가 강해진다.
2. **개념 태그 브라우징**: keyword_title을 과목 하위 태그처럼 노출 —
   "행정법 > 처분성" 틀린 문항 모아보기. 태그 정규화(유사 키워드 병합)가
   필요해지면 그때 AI 일괄 정리 배치를 한 번 돌린다. `unit_tag` 백필도 이때 함께.
3. **전국 오답률 통계**: `cbt_attempt_answers`를 문항별로 집계해 "응시자 68%가
   틀린 문제" 배지, "고난도만 섞어풀기" 프리셋. 익명 집계라 개인정보 부담 없음.
   응시 데이터가 충분히 쌓인 뒤에 의미가 생긴다(표본 적으면 오해만 유발).
4. **문항 메모**: 오답 카드에 사용자 메모 1필드. 구현은 얇지만 "내 노트"라는
   소유감을 만든다.
5. **오답노트 PDF 내보내기**: 시험장 직전 복습용 인쇄물. Phase 1 화면의 인쇄
   최적화로 시작해 수요 보고 전용 생성으로.
6. **D-day 학습 플랜**: 목표 시험일 등록 → 남은 기간에 미극복 문항·취약 개념을
   주 단위로 배분. AI 진단(Phase 3)의 확장판이며 가장 마지막.

## 구현 순서와 의존 관계

```
Phase 1 (모아보기)  ──→  Phase 2 (섞어풀기: user_question_status 도입)
                              │
                              └──→  Phase 3 (AI 진단: 진단→모아보기/섞어풀기 딥링크)
                                        └──→ Phase 4 (복습 스케줄·태그·통계·플랜)
```

- 1 → 2 → 3 순서 고정을 권장. 진단부터 만들면 "약점을 알려줬는데 할 수 있는 게
  없는" 리포트가 된다. 모아보기·섞어풀기가 진단의 처방전 역할을 한다.
- 각 Phase는 독립 배포 가능한 크기로 자른다. 특히 Phase 2의
  `user_question_status` 도입은 마이그레이션+백필이 끼므로 별도 배포로 격리.

## 공통 리스크 메모

- **중복 시험지 표시 통합(dedup)과의 상호작용**: 같은 시험지가 track만 다르게
  두 행 존재할 수 있다(AGENTS.md 참조). 오답노트·섞어풀기는 응시한 paper_id
  기준이라 당장은 안전하지만, "같은 과목 문항 모아보기"에서 병합 그룹의 두 행에
  각각 응시 기록이 있으면 같은 문항이 두 번 보일 수 있다 — Phase 1에서
  `dedup-papers.ts`의 그룹 키로 같은 처리를 해줄 것.
- **정답·해설 RLS**: 어떤 신규 화면/채점 경로도 `paper_answers`·
  `question_explanations`를 클라이언트에서 직접 읽게 하지 말 것(전부 service role
  경유 서버 조립 — 기존 `wrong-notes.ts` 패턴 유지).
- **해설봇 RLS 회귀**: `user_question_status` 등 신규 테이블/정책 작업 시
  해설봇 계정의 `question_explanations` 쓰기 권한을 깨지 않는지 확인
  (과거 스키마 변경으로 조용히 깨진 전적 — AGENTS.md).
- **측정**: 각 Phase에 최소 지표 하나씩 — 모아보기 진입률, 섞어풀기 완주율,
  진단 재요청률(다음 날 또 받는가). Phase 4 선별은 이 숫자로 한다.
